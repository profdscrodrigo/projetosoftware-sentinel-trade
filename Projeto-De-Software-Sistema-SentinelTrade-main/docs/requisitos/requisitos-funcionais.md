# Requisitos Funcionais

Os requisitos funcionais representam as funcionalidades que o SentinelTrade deve realizar.

| ID | Requisito | Descrição |
|---|---|---|
| RF-01 | Autenticação | O sistema deve permitir a autenticação dos usuários utilizando MFA. |
| RF-02 | Gerenciamento de Contas | O sistema deve permitir manter os dados das contas dos investidores. |
| RF-03 | Gerenciamento de Carteiras | O sistema deve permitir manter os dados das carteiras dos investidores. |
| RF-04 | Gerenciamento de Ativos | O sistema deve permitir manter os dados dos ativos disponíveis para negociação. |
| RF-05 | Gerenciamento de Limites | O sistema deve permitir manter os limites financeiros dos investidores. |
| RF-06 | Consulta de Cotações | O sistema deve permitir consultar as cotações dos ativos. |
| RF-07 | Recebimento de Cotações | O sistema deve receber cotações de um provedor externo. |
| RF-08 | Envio de Ordem | O sistema deve permitir o envio de ordens de compra e venda. |
| RF-09 | Cancelamento de Ordem | O sistema deve permitir solicitar o cancelamento de ordens. |
| RF-10 | Consulta de Ordem | O sistema deve permitir consultar as ordens realizadas. |
| RF-11 | Validação de Ordem | O sistema deve validar saldo, posição em carteira, limite de risco e situação do mercado antes de transmitir uma ordem. |
| RF-12 | Transmissão de Ordem | O sistema deve transmitir ordens válidas para a Bolsa/Corretora simulada. |
| RF-13 | Acompanhamento de Ordem | O sistema deve permitir acompanhar o ciclo de vida das ordens. |
| RF-14 | Histórico de Operações | O sistema deve permitir consultar o histórico das operações. |
| RF-15 | Auditoria | O sistema deve registrar eventos relevantes das operações para auditoria. |
| RF-16 | Notificações | O sistema deve notificar o investidor sobre execução, rejeição, cancelamento ou falha. |
| RF-17 | Prevenção de Duplicidade | O sistema deve impedir o processamento duplicado de ordens. |
